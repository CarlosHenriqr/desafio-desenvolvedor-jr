# Roteiro de Avaliação - Pull Request

## Análise do Pull Request (20%)

### Qualidade da Descrição
- **Excelente**: Template preenchido completamente, explicações claras
- **Bom**: Maioria dos campos preenchidos, boa descrição
- **Regular**: Preenchimento básico, falta detalhes
- **Insuficiente**: Template mal preenchido ou incompleto

### Organização dos Commits
- **Excelente**: Commits organizados, mensagens descritivas
- **Bom**: Commits coerentes, mensagens adequadas
- **Regular**: Poucos commits, mensagens básicas
- **Insuficiente**: Commits desorganizados ou mensagens ruins

## Análise do Código (30%)

### Correções Implementadas
- **Excelente**: Todos os bugs corrigidos corretamente
- **Bom**: Maioria dos bugs corrigidos
- **Regular**: Alguns bugs corrigidos
- **Insuficiente**: Poucos ou nenhum bug corrigido

### Qualidade das Soluções
- **Excelente**: Soluções elegantes e eficientes
- **Bom**: Soluções funcionais e adequadas
- **Regular**: Soluções básicas mas funcionais
- **Insuficiente**: Soluções inadequadas ou não funcionais

## Documentação do Processo (25%)

### Arquivo SOLUCOES.md
- **Excelente**: Processo detalhado, ferramentas mencionadas
- **Bom**: Boa descrição do processo de debugging
- **Regular**: Documentação básica do processo
- **Insuficiente**: Documentação inadequada ou ausente

### Explicação dos Bugs
- **Excelente**: Explica causa raiz e como identificou
- **Bom**: Boa explicação dos problemas encontrados
- **Regular**: Explicação básica dos bugs
- **Insuficiente**: Não explica adequadamente os problemas

## Apresentação (25%)

### Demonstração
- **Excelente**: Mostra projeto funcionando, explica cada correção
- **Bom**: Demonstra funcionalidades corrigidas
- **Regular**: Mostra que funciona, explicação básica
- **Insuficiente**: Não consegue demonstrar adequadamente

### Processo de Debugging
- **Excelente**: Explica metodologia, ferramentas, raciocínio
- **Bom**: Descreve bem o processo usado
- **Regular**: Explicação básica do processo
- **Insuficiente**: Não consegue explicar o processo

## Perguntas para a Entrevista

### Sobre o Pull Request
- "Explique como organizou seus commits"
- "Por que escolheu essas mensagens de commit?"
- "Como decidiu o que documentar no PR?"

### Sobre o Processo
- "Qual foi o primeiro bug que encontrou?"
- "Como soube que era um problema de conversão de tipos?"
- "Que ferramentas usou para debuggar?"
- "Se fosse trabalhar em equipe, como comunicaria esses bugs?"

### Cenários Hipotéticos
- "Se esse fosse um projeto real, como preveniria esses bugs?"
- "Como você faria code review deste código?"
- "Se um colega fizesse esse PR, que feedback daria?"

## Sinais Positivos
- PR bem estruturado e documentado
- Commits organizados com mensagens claras
- Documentação detalhada do processo
- Consegue explicar o raciocínio
- Demonstra aprendizado com o processo

## Sinais de Atenção
- PR mal documentado ou incompleto
- Commits desorganizados
- Não consegue explicar como encontrou os bugs
- Soluções funcionam mas não entende o porquê
- Não demonstra processo sistemático de debugging
